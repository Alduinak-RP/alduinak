# Interaction prompts — the rollover, in our own words

The vanilla rollover **text** is faded out and replaced with a CEF prompt at
the vanilla spot (lower center); the vanilla key glyph stays and pairs with
our wording. The bounty board says "Read Notice Board", player characters
say "Interact" over an introduction- and mask-aware name, everything else
keeps its display name with a verb picked from its base form type.

- Client piece: `skymp5-client/src/services/services/interactionPromptService.ts`
- Front piece: `skymp5-front/src/features/interactPrompt/` (widget type `interactPrompt`, id 27)

## How it works

- **Hiding vanilla text**: every `update` tick the service writes
  `_root.HUDMovieBaseInstance.RolloverText._alpha = 0` into the `HUD Menu`
  movie via `Ui.setFloat`. Alpha is used because the engine rewrites the
  rollover's text and `_visible` on every crosshair change but leaves alpha
  alone; it is the same technique skyrim-platform itself uses to hide the
  cursor (`FridaHooks.cpp`, `_root.mc_Cursor._alpha`). The vanilla key glyph
  (`RolloverButton`) is deliberately left visible - it is the [E] the player
  sees, and the engine fights attempts to hide it anyway.
- **The custom prompt**: `crosshairRefChanged` drives a passive widget (never
  focused, pointer-events none, chat-style push) at lower center: VERB over
  Label. Label = the ref's display name (so housing names and
  `setDisplayName` decor flow through); no name means no prompt, matching
  vanilla.
- **Player characters** (remote id in the dynamic `0xff` space): verb
  "Interact"; the name follows introductions (`ff_knownIds` owner prop, else
  "Stranger"), and a masked player already carries "Masked Person" as their
  appearance name, so the mask holds. The clone's engine activation is
  blocked (`blockActivation`) so the activate key belongs entirely to the
  interaction menu: `PlayerActionService` now opens on **E**
  (`interactMenuKeyCode`) instead of X, silently ignoring anything that is
  not a player character. World NPCs keep vanilla activation and read
  "Talk" over their name.
- **Verbs by base type**: Door Open/Unlock, Container Search/Unlock,
  Activator Activate, Furniture Use, Book Read, Flora/Tree Harvest (skipped
  when harvested), item types Take. The board base (`12cb:Missives.esp`,
  resolved through `Game.getFormFromFile` so load order cannot break it)
  gets Read + "Notice Board".
- Apart from the blocked player clones, the engine still performs the real
  activation; the server intercepts activations where it wants to (the
  bounty board does).

## Switches and verification

- `customPrompts: false` in the `skymp5-client` settings block disables the
  service entirely (no GFx writes, no widget) - the vanilla rollover returns.
- First in-game check after a client build: point at a door. Custom prompt
  visible, vanilla text gone. If the vanilla rollover survives, the GFx
  paths need adjusting for the shipped hudmenu - probe with
  `Ui.getString("HUD Menu", "_root.HUDMovieBaseInstance.RolloverText.text")`
  while pointing at something activatable (non-empty means the path root is
  right).

## Deployment

Client + front: manager **Build Client**, players re-download via the
launcher. No server-side artifacts affected.
