# Interaction prompts — the rollover, in our own words

The vanilla "[E] Activate <name>" rollover is faded out and replaced with a
CEF prompt the server side of the game can phrase freely. The bounty board
says "Read Notice Board"; everything else keeps its display name with a verb
picked from its base form type.

- Client piece: `skymp5-client/src/services/services/interactionPromptService.ts`
- Front piece: `skymp5-front/src/features/interactPrompt/` (widget type `interactPrompt`, id 27)

## How it works

- **Hiding vanilla**: every `update` tick the service writes
  `_root.HUDMovieBaseInstance.RolloverText._alpha = 0` and
  `...RolloverButton._alpha = 0` into the `HUD Menu` movie via `Ui.setFloat`.
  Alpha is used because the engine rewrites the rollover's text and
  `_visible` on every crosshair change but leaves alpha alone; it is the same
  technique skyrim-platform itself uses to hide the cursor
  (`FridaHooks.cpp`, `_root.mc_Cursor._alpha`). The GFx paths are the vanilla
  hudmenu members, which SkyUI's hudmenu preserves (SkyUI is the only
  interface mod in the modlist that touches hudmenu.swf, and it is additive).
- **The custom prompt**: `crosshairRefChanged` drives a passive widget (never
  focused, pointer-events none, chat-style push) showing `[key] VERB Label`.
  The key glyph reads the player's real Activate bind via
  `Input.getMappedKey`. Label = the ref's display name (so housing names and
  `setDisplayName` decor flow through); no name means no prompt, matching
  vanilla. Actors are skipped - nametags already cover them.
- **Verbs by base type**: Door Open/Unlock, Container Search/Unlock,
  Activator Activate, Furniture Use, Book Read, Flora/Tree Harvest (skipped
  when harvested), item types Take. The board base (`12cb:Missives.esp`,
  resolved through `Game.getFormFromFile` so load order cannot break it)
  gets Read + "Notice Board".
- **Purely cosmetic**: the engine still performs the real activation; the
  server intercepts activations where it wants to (the bounty board does).
  Nothing here consumes input.

## Switches and verification

- `customPrompts: false` in the `skymp5-client` settings block disables the
  service entirely (no GFx writes, no widget) - the vanilla rollover returns.
- First in-game check after a client build: point at a door. Custom prompt
  visible, vanilla text gone. If the vanilla rollover survives, the GFx
  paths need adjusting for the shipped hudmenu - probe with
  `Ui.getString("HUD Menu", "_root.HUDMovieBaseInstance.RolloverText.text")`
  while pointing at something activatable (non-empty means the path root is
  right).

## Deployment

Client + front: manager **Build Client**, players re-download via the
launcher. No server-side artifacts affected.
