# Roleplay Survival Loop — Bleedout, Arrest & Carry

This covers the interlinked "survival loop" features:

- **8. Bleedout** — at 0 health a player kneels instead of dying. A further
  hit from a player, damage over time, a logout or the 15 s timer kills them;
  healing, a capture or a carry saves them.
- **9. Arrest** — binding the hands of a player, at once when they are
  bleeding out.
- **10. Carry** — picking up a consenting player, or a player in bleedout,
  which ends their bleedout.

The server side is `skymp5-server/ts/systems/bleedoutSystem.ts` (bleedout),
`captureSystem.ts` (arrest and carry) and the native `onKillAttempt` gate in
`MpActor`. Client pieces:

- `skymp5-client/src/services/services/restraintService.ts` — local-player
  restraint (bound hands + carried) via the `restraintState` CustomPacket, and
  the bleedout kneel via `bleedoutState`.
- `skymp5-client/src/sync/animation.ts` — `forcedSyncAnims` syncs the
  bound-hands, carry and bleedout poses to other clients.

All poses used here (`OffsetCarryBasketStart`, `OffsetBoundStandingStart`,
`OffsetStop`, `bleedOutStart`, `bleedOutStop`) are **vanilla Skyrim
behaviour-graph events — no ESP required.**

## 8. Bleedout

- **Going down**: before a player dies at 0 health, the native server fires
  `onKillAttempt(actorId, killerId)` from `MpActor::NetSetPercentages` (weapon
  and spell hits, `mp.set` percentages, `DamageActorValue`) and
  `MpActor::SetPercentage` (the player's own health report: damage over time,
  falls). BleedoutSystem refuses it, so the server holds the player at 1%
  health and never sends them 0. They kneel in the vanilla bleedout pose, cannot
  move, fight, sneak, cast, activate, eat, drink or open menus, and are told how
  long they have (a potion they drink anyway is handed back without effect). The player who downed them is told too. NPCs, and admins in god or
  ghost mode, never go down. Without the native server build the gate never
  fires and players die at once, as before.
- **Dying**: a further hit from another player kills at once, and the
  gamemode's `onDeath` writes it to `pvp.log`. Damage over time kills after a
  1 s grace (the victim's own stale report of 0 right after the downing does
  not count). NPC hits on a downed player are refused. Logging out, or leaving
  for character select, while downed is a death. After `bleedoutSeconds` (15)
  the player dies as usual: the normal respawn follows, at a temple or in the
  afterlife's hall.
- **Admin modes**: a hit from an admin in Smite kills a player outright, never
  downing them, and a hit from an admin in Heal on Hit stands a downed player
  up at full health instead of finishing them.
- **Getting up**: healing back to `bleedoutHealedHealth` (25%) of max health
  stands the player up. A Restrain or Carry from the X menu takes a downed
  player at once, with no prompt, and ends the bleedout; they keep their low
  health.
- **Logs**: deaths the native kill does not report (timer, damage over time,
  logout, a light finishing hit) go to `pvp.log` when another player downed or
  hit them; every bleedout event is logged as `[bleedout] ...`.
- **State**: `private.bleedout` (`{ since, downerId }`) mirrors a downed player
  for other systems (`isBleedingOut` in `actorUtil.ts`); a leftover mirror is
  cleared when the character is next picked. A downed player cannot restrain,
  carry, release, search or trade. On their own client they are a ghost, so
  the swings of NPCs they host pass through; the server judges every hit.
- **Tuning**: `bleedoutSeconds` and `bleedoutHealedHealth` in
  `server-settings.json` (`docs_server_configuration_reference.md`).

## 9. Arrest — bind hands

A player may bind the hands of a victim **who is in bleedout** (feature 9).
Guards of a hold get this right via the factions system (feature 6).

### Client (implemented)

The gamemode sends, to the **victim's** client:

```json
{ "customPacketType": "restraintState", "boundHands": true }
```

`RestraintService` plays the bound-hands pose (`OffsetBoundStandingStart`) and
disables fighting/sneaking/activation, while leaving movement enabled so the
prisoner can be marched. To release:

```json
{ "customPacketType": "restraintState", "boundHands": false }
```

The pose is synced to nearby players via `forcedSyncAnims`, so everyone sees the
bound hands, not just the victim.

### Gamemode TODO

1. Validate the actor is **eligible** to be bound (in bleedout, or already
   subdued) — don't allow binding an upright, free player.
2. Validate the **binder's** permission: a guard of the hold (faction check,
   feature 6) or an admin. Reject otherwise.
3. Persist the bound state on the victim (e.g. `private.boundHands`) so it
   survives reconnects and is re-sent on login, and re-send `restraintState`
   when the victim respawns/gets up so the pose re-applies.
4. Gate hands-bound actions server-side too (can't equip/attack/loot) — the
   client lock is cosmetic/UX, not security.

## 10. Carry

A player can pick up either a **consenting** player or a player **in bleedout**.
Picking up a player in bleedout **ends their bleedout** (§8).

### Client (implemented + existing)

- **Carrier pose** — the gamemode's existing `CarryAnimSystem` drives the
  carry animation (`OffsetCarryBasketStart`) on the carrier; it already syncs.
- **Carried lock** — the gamemode sends, to the **carried** player's client:

  ```json
  { "customPacketType": "restraintState", "carried": true }
  ```

  `RestraintService` immobilises them (`setDontMove`, controls disabled) so the
  server can move the body, while leaving the camera free. Release with:

  ```json
  { "customPacketType": "restraintState", "carried": false }
  ```

`boundHands` and `carried` are independent flags and may be combined (a bound
prisoner can also be carried).

### Gamemode TODO

1. **Consent / eligibility** — allow carry only if the target is in bleedout
   **or** has consented (a prompt/`/carryaccept`-style flow you define).
2. **Move the body** — while carried, keep the victim positioned on/just behind
   the carrier each tick (server-side `moveTo`/position update, or a follow
   offset). Mark the carried actor so movement sync doesn't fight it.
3. **End bleedout** — a carry of a bleeding-out player ends the bleedout
   (`CaptureSystem.rescueDowned`); a carried player hit to 0 is dropped and
   bleeds out again.
4. **Put down / drop** — on release send `carried: false`.

## Message reference (quick)

| Packet (`customPacketType`) | Direction | Purpose |
| --- | --- | --- |
| `restraintState` `{ boundHands?, carried? }` | Server → victim client | Apply bound-hands / carried state |
| `bleedoutState` `{ downed, seconds?, died? }` | Server → downed player's client | Kneel and lock controls, or stand up (no stand-up when `died`) |
| *(CarryAnimSystem, existing gamemode)* | Server → clients | Carrier pose |

All restraint/bleedout **rules, timers, permissions and persistence are
server-authoritative.** The client services only render the resulting state.
